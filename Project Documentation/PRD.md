# Product Requirements Document: LearnMate AI

## 1. Summary
LearnMate AI helps students understand study material and check their understanding. A student pastes text, receives a summary, takes an auto-generated five-question quiz, and sees a score with explanations. All generation uses a real open-weight model (Google Gemma, default `gemma-4-26b-a4b-it`) hosted by the free Gemini API, called only from the backend.

## 2. Problem
Students read passively and rarely test themselves. Many AI tools cost money or need setup. LearnMate uses a free hosted Gemma model; the trade-off is that text is sent to Google (and, on the free tier, may be used to improve Google products; unconfirmed).

## 3. Goals
1. Working, demo-ready app that runs locally on any Windows laptop and deploys to Render (API) and Vercel (web).
2. Genuine open-weight (Gemma) model integration with no simulated output.
3. Focused feature set: summary, quiz, scoring.
4. Public open-source repository (MIT) with a useful README.
5. Honest, realistic deployment plan with accurate free-tier caveats.

## 4. Non-goals
Accounts, saved history, databases, file/PDF upload, streaming, multiple models, analytics, mobile apps, guaranteeing factual correctness of model output.

## 5. Users
- **Student:** wants quick comprehension and self-testing.
- **Hackathon presenter (primary operator):** needs a reliable live demo on modest hardware and clear evidence that a real model runs.
- **Judge/reviewer:** inspects the repo, README and architecture.

## 6. User stories
1. As a student, I paste text and get a summary in my chosen length.
2. As a student, I get a five-question quiz at Easy/Medium/Hard difficulty.
3. As a student, I answer, submit, and see my score, correct answers and explanations.
4. As a student, I cannot change answers after submitting unless I retake or generate new questions.
5. As a presenter, I see whether the backend, API key and model are ready before I start.
6. As a presenter, I see model name, time and tokens for each result.
7. As a user, I get a clear message when something fails.

## 7. Functional requirements

### Input
- FR-1 Text area for pasted text; character counter against a configurable maximum (default 12,000).
- FR-2 Empty, too-short (default under 50 chars) and too-long input are rejected in the UI and on the server with clear messages.
- FR-3 "Use example" fills the input only. "Clear" resets input, results and in-flight work.

### Summary
- FR-4 Short, medium and detailed lengths.
- FR-5 Generated by the hosted Gemma model from the supplied text only (prompt forbids outside facts).
- FR-6 Displayed in a card with copy button and idle/loading/success/error states.

### Quiz
- FR-7 Exactly 5 questions, each with exactly 4 distinct options, exactly one correct answer and a short explanation.
- FR-8 Easy/Medium/Hard difficulty.
- FR-9 Server validates structure; invalid output triggers at most one repair attempt, then a clear error.
- FR-10 User selects answers; submit is enabled only when all five are answered.
- FR-11 After submit: score, correct answers, per-question explanations; answers locked.
- FR-12 "Retake quiz" resets answers; "New questions" regenerates.

### Combined mode
- FR-13 One primary action generates summary then quiz sequentially (never in parallel).
- FR-14 If the summary fails, the quiz is not attempted.

### Status and errors
- FR-15 Health badge shows backend / API key / model / rate-limit status without triggering generation.
- FR-16 Errors are consistent JSON and mapped to friendly messages for: missing or rejected API key, rate limit, provider unreachable, model not found, timeout, malformed output, busy server, validation errors.

### API
- FR-17 `GET /api/v1/health`, `POST /api/v1/learning/generate-summary`, `/generate-quiz`, `/generate` as defined in `Architecture.md`.

## 8. Non-functional requirements
- NFR-1 **Genuine AI:** no hardcoded, static or simulated AI output anywhere.
- NFR-2 **Frugal:** one generation at a time; no generation at startup or in health checks; configurable output limits to conserve free-tier quota.
- NFR-3 **Security:** model output treated as untrusted; no stack traces or env values sent to the browser; CORS allow-list (exact origins, no wildcard in production); the API key exists only in backend env; no secrets in the repo; logs never contain keys, requests or study text.
- NFR-4 **Configurability:** model, API key, base URL, timeouts, token limits, thinking level, CORS origins and input limits via environment variables.
- NFR-5 **Accessibility:** labelled inputs, keyboard-operable controls, visible focus, non-colour-only feedback.
- NFR-6 **Responsiveness:** usable on laptop and phone widths.
- NFR-7 **Maintainability:** typed code, unit tests for validation, parsing and scoring.
- NFR-8 **Honesty:** UI and docs state that output may be wrong.

## 9. Acceptance criteria
| ID | Criterion |
| --- | --- |
| AC-1 | `npm install` then `npm run dev` starts backend (4000) and frontend (5173) with no model call, even without a key. |
| AC-2 | `/health` returns 200 `ok` with a valid key and model; 503 `degraded` with `provider.state` and a helpful message otherwise. `/health/live` is always 200. |
| AC-3 | With the example text, "Generate summary and quiz" shows a summary, then a quiz, both with a footer naming the Gemma model, duration and tokens. |
| AC-4 | Every returned quiz has 5 questions x 4 distinct options, `correctIndex` 0-3, non-empty explanations (enforced by `quizSchema`). |
| AC-5 | Submitting shows the correct score; correct/incorrect options are marked with icons and text; explanations appear; radios are disabled. |
| AC-6 | Submit is disabled until all questions are answered. |
| AC-7 | Empty input shows an inline error without calling the server; over-limit input disables generation buttons. |
| AC-8 | With no/invalid key, generating shows a clear message (503 `AI_NOT_CONFIGURED` / 502 `AI_AUTH_ERROR`) and the key is never echoed. |
| AC-9 | A wrong `GEMMA_MODEL` shows `MODEL_NOT_FOUND` guidance; quota exhaustion shows `AI_RATE_LIMITED`. |
| AC-10 | Malformed model quiz output is repaired once or returns `MODEL_OUTPUT_INVALID`; never a malformed quiz in the UI. |
| AC-11 | A second concurrent generation request gets 429 `SERVER_BUSY`. |
| AC-12 | `npm test`, `npm run typecheck`, `npm run build` pass. |
| AC-13 | Repo contains MIT `LICENSE`, `.env.example` files, no `.env`, and a README with setup, API, limitations, deployment and demo script. |
| AC-14 | README documents Render + Vercel deployment, required env vars, and the verified vs unverified free-tier facts. In production the server refuses to start without explicit non-wildcard `CORS_ORIGINS`. |

Status of each criterion is tracked in `Phases.md` (Phase 4 and 5 verification items).

## 10. Risks
Shared free-tier quota (unpublished per model) and 429s; provider availability by region; Render cold starts; quiz JSON malformation; unverified live behaviour of JSON mode/thinking settings. Mitigations are in `Memory.md` and `README.md` troubleshooting.

## 11. Demo definition
Follow the "Demo script" in `README.md`: show readiness badge, paste/load text, generate, show real-model evidence (model/time/token footer, different input gives different output), take the quiz (one wrong), review explanations, explain architecture.
